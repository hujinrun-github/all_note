# 网页端语音输入与计划生成方案

日期：2026-11-19
状态：网页首版核心闭环已实施
范围：现有 React 网页，覆盖桌面浏览器与手机浏览器

### 实施与验证记录

已接入全局捕获、工作台和项目详情入口；实现网页录音、现有配置转写、文字校对、异步计划生成、任务编辑、有限窗口冲突检查和原子批量提交。支持自动保存/恢复、明确新建项目、仅保存任务草稿、幂等重放、旧结果保护与录音清理。使用与升级步骤见[网页语音计划指南](../../web-voice-planning.md)。

本地验证：前端 `npm run test:regression` 通过，包含 lint、423 个 Vitest、生产构建和三浏览器 UI（76 通过，8 个既有用例按设备跳过）；新增语音计划 UI 12 项全部通过。后端 `go test ./cmd/... ./internal/...` 通过，计划存储/作业及相关运行时 race 检查通过。已验证真实 WebM/Opus、MP4/AAC 解码，以及隔离 SQL + HTTP provider 适配的完整提交链路。

验证边界：网页录音自动化使用合成音频，外部 ASR/LLM 使用测试服务；没有完成 HTTPS 真机麦克风和当前线上识别效果验收。本机标准 v2 测试数据库缺失，指定 PostgreSQL 测试地址连接超时/EOF，实际 PostgreSQL 集成仍待验证。没有重新 cutover、开启 legacy writes 或发布线上服务。

初版通过任务卡片和现有排程表单预览安排；逐字段来源标记与展开未来执行次数属于后续预览增强。下文保留完整设计目标，已交付使用方式以指南为准。

## 1. 产品目标与推荐范围

用户在网页中说出一个目标或一组安排，系统转成可编辑的文字和计划草稿。用户核对任务、项目、日期、时间和重复规则后，一次确认创建到现有 v2 任务与日历中。

核心流程：**打开入口 → 录音 → 核对文字 → 生成草稿 → 调整与确认 → 创建任务和安排。**

第一版提供两种输入、共用同一生成流程：

- 语音输入：点击开始、点击结束，录完后转写。
- 文字输入：直接描述需求，也可编辑转写结果后生成。

第一版支持一次性事项、多事项拆解、日/周/月重复，以及有目标的任务分解。支持已有项目、系统收件箱或用户明确选择的新项目；每份草稿只提交到一个项目，降低批量确认的复杂度。生成建议可以包含阶段分组，但第一版不创建或覆盖 Roadmap。

后续再扩展实时转写、补充口述修改草稿、跨项目生成、已有任务重排、长期路线图和跨设备草稿同步。当前不涉及原生 App 的录音入口。

以下结论来自当前工作区源码，没有启动服务或核实线上配置。

| 已有基础 | 代码位置 | 方案影响 |

| v2 Task、Schedule、Occurrence 与时区校验 | `backend/internal/taskdomain/task_factory.go`、`schedule.go` | 最终写入规范任务模型，日历读取同一批执行实例 |

必须处理的差异：

1. 现有 `voice.create` 会创建 backing Note，旧转写完成还会写笔记正文（`mobilev2service/content_commands.go:507`、`storage/sqlite/transcription_worker.go:178`）。临时口述计划采用独立草稿，不默认新增笔记。
2. 现有路线图生成仅适用于 learning 项目，并直接创建/替换节点（`handler/roadmap_v2.go:151`、`:215`）。新功能只复用 AI 基础能力，另建预览与确认用例。
3. 旧音频白名单没有 WebM/Opus，旧 worker 使用固定 `.m4a` 文件名（`service/native.go:518`、`transcriptionjob/worker.go:79`）。网页录音须补齐格式处理。
4. 现有 CreateTask 每次独立生成 ID、独立事务；任务初始 lifecycle 为 draft（`taskapp/facade.go:321`、`taskdomain/task_factory.go:87`）。新增批量提交用例，显式处理 publish 与项目状态。
5. 当前个人工作台后端重构尚未完成通用 Capture/Jobs 入口；本功能使用窄的计划草稿模块，保持相同的工作区解析和事务规则，不把整套重构作为前置条件。

## 3. 网页入口与界面

### 3.1 入口

| 位置 | 行为 |
| --- | --- |
| 全局“快速捕获” | 提供“添加任务 / 生成计划”两个模式；后者有“开始录音”和文字输入框 |
| 工作台快捷操作 | “语音计划”直接打开同一面板 |
| 项目详情 | “生成计划”带入当前 `project_id`，面板明确展示目标项目 |
| 日历 | 可在后续批次增加带日期的同一入口；日期仅作为可见上下文，不覆盖用户口述日期 |

不增加主导航栏目。桌面使用宽对话框，手机网页使用全屏对话框；二者共享业务状态和表单。手机工作台快捷操作确保在窄屏也可直接进入，不依赖桌面顶栏是否显示。

### 3.2 输入与转写

- 点击“开始录音”后请求麦克风权限，录制中显示明显状态、计时、“结束录音”“取消”。结束、取消或离开时释放媒体轨道。
- 第一版建议每段最长 3 分钟、最大 20 MiB，作为可配置产品限制；服务端同时校验真实时长、体积和解码资源消耗。
- 结束后上传并转写，显示“正在上传 / 正在转写”；失败时分别重传或重试，不要求重新口述。
- 转写完成后展示可编辑文本和“生成计划草稿”。用户可以先纠正专有名词和时间。
- 权限拒绝、浏览器不支持录音或无麦克风时，面板保留文字输入能力。
- 录音处理中刷新不能承诺保留浏览器内尚未上传的字节。上传完成后，服务端草稿可恢复；第一版不增加本地离线录音队列。
- 同一入口展示“继续上次草稿 / 最近未完成草稿”。文字和表单编辑按顺序防抖保存，显示“保存中 / 已保存 / 保存失败”；生成或确认前先完成待保存修改。关闭面板时如果还有未上传音频或未保存修改，提示用户处理。

### 3.3 草稿预览与确认

桌面按“原始描述 / 计划预览”两区展示，手机按步骤显示，避免横向宽表格。

计划预览包括：

- 计划标题、归属项目、时间范围和时区。
- 每项任务的勾选框、标题、说明、日期/时段、重复规则。
- “用户明确要求”“系统建议”“待补充”的字段标记，便于理解哪些安排来自推断。
- 重复任务显示规则和有限日期范围内的执行预览，例如未来 7 天；显示“任务数”和“执行次数”各自口径。
- 必须补充的问题、时间冲突、疑似重复任务。
- “保存草稿”“重新生成”“确认创建 N 个任务”。重新生成先保存修订版本，用户手动编辑过的内容不被迟到结果覆盖。

所有可执行变化在预览里明确展示。创建成功显示“已创建 N 个任务”，提供“查看本次创建”“查看项目”“查看日历”。第一版不提供跨版本无条件批量删除式撤销。

每份草稿只能成功提交一次。未勾选项在本次不创建，提交前显示其数量；成功后保留原稿用于查看，需要继续创建时复制未选项为一份新草稿。复制是明确操作，不自动重复提交已创建项。

### 3.4 例子

假设输入时为 2026-11-19、时区为 Asia/Shanghai：

> 帮我安排下周的日语学习，周一到周五晚上八点到八点半复习单词，周三晚上八点半到九点练听力，周末不安排。

草稿可展示：

| 任务 | 安排 | 规则与结束 |
| --- | --- | --- |
| 复习日语单词 | 2026-11-23 起，20:00–20:30 | 周一至周五，2026-11-27 结束 |
| 日语听力练习 | 2026-11-25，20:30–21:00 | 单次 |

确认前显示：**2 个任务，下周共 6 次执行，周末没有安排。** 项目由用户选择；如存在多个同名或相近项目，不依据名称直接决定身份。

若原话只有“每天晚上复习半小时”，系统保留“每天、晚上、半小时”的要求，将起始日期和具体开始时间列为待补充或明确建议。用户可选择先保存未安排任务，此时明确显示“暂不启用每日重复”，原始频率和时长约束保留在草稿及任务说明中。

## 4. 生成与排程规则

### 4.1 AI 与应用各自负责的事

AI 输出有版本的结构化提案，包括目标、任务分解、约束、可选建议和澄清问题；应用负责 JSON schema、权限、日期、重复规则、领域不变量和冲突校验。AI 不执行 SQL，也不直接调用创建/修改任务接口。

生成只使用当前工作区内必要的上下文：用户确认的文字、选定项目、允许的日程规则、可用时间和选定窗口内的已有安排。第一版不默认发送全部笔记或项目内容。

结构化输出建议字段：`schema_version`、`title`、`target_project`、`items[]`、`constraints`、`assumptions[]`、`clarifications[]`。每项有稳定的 `item_id`、`selected`、`title`、`description`、`schedule`、可选 `due_at`、来源片段及建议字段；服务端分配业务实体 ID。

### 4.2 时间、重复和截止

| 用户表达 | 系统处理 |
| --- | --- |
| 明天、下周一 | 按草稿输入时保存的基准时间和用户确认的 IANA 时区解释，预览显示绝对日期；重试不过午夜漂移 |
| 明天完成报告 | 可生成带日期任务；没有具体时刻不填默认 09:00 |
| 晚上学习半小时 | 保留时长约束；具体时刻需要补充，或展示可接受的建议 |
| 周一到周五 | 映射 weekly weekdays；不自动等同包含调休规则的法定工作日 |
| 每天、每周、每月 | 映射现有 recurrence 规则，一个重复 Task 产生多个 Occurrence |
| 隔两周周一 | 映射 weekly interval=2，并明确起始日 |
| 每月最后一个工作日 | 第一版不强行映射到不支持的规则；要求调整或保留未安排草稿 |
| 周五之前交稿 | 区分截止时间与执行时间；具体截止瞬间不明确时先补充，确认后独立写入 due_at |
| 下个月完成一个学习目标 | 可以拆解并建议节奏；起止日期、每日容量和具体安排在预览中标为建议 |

时区缺失时使用浏览器检测值作为可见默认，提交时校验，不依赖服务器本地时区。遵循已有 Schedule 的 DST 歧义/不存在时间错误，不静默改时间。跨日、重复结束日期和全天事项使用现有领域语义。

第一版仅支持单次任务的独立截止时刻；“每次执行后两天截止”等重复截止偏移规则保留为未支持约束，不伪装成已实现。

### 4.3 冲突与信息不足

- 必填缺口阻止对应项目提交，允许取消勾选；不影响无关事项的编辑。一次汇总关键问题，避免每个字段来回追问。
- 对有明确时段的候选执行，与已有日程和草稿内部按时间区间检测重叠；相邻首尾相接不算冲突。
- 第一版冲突检查限定在预览窗口，默认未来 14 天并可调整。不声称无限重复计划永久无冲突。
- 提供“修改时间”“保留重叠安排”，后者明确记录用户选择。时间安排变化、草稿修订或提交时发现新的冲突，需要重新确认。
- 第一版确定为有限窗口内的冲突提示与提交前复查，不承诺严格排他；其他入口的并发写入仍可能在检查后产生新的重叠。未来需要严格排他时，再统一所有排程写路径的锁/版本协议，不把全域排程改造放进本次前置条件。
- 未安排、仅日期和截止标记不推导为占用一整天的时间块。

## 5. 技术结构

保持 Go/Gin 模块化单体与现有 React 状态管理。新增小范围的计划输入、生成和提交用例，均通过当前已认证工作区运行时解析，不走 legacy 任务写入。

```mermaid
flowchart LR
  W[网页录音或文字] --> D[计划草稿]
  D --> T[异步语音转写]
  T --> E[用户核对文字]
  D --> E
  E --> G[AI 生成结构化提案]
  G --> V[规则校验与冲突预览]
  V --> P[用户编辑并确认]
  P --> C[批量提交用例]
  C --> R[v2 Task / Schedule / Occurrence]
  R --> U[工作台 / 项目 / 日历]
```

### 5.1 网页录音与音频处理

使用 `getUserMedia` 和 `MediaRecorder`，按 `MediaRecorder.isTypeSupported()` 检测格式，保留真实 MIME 和扩展名。覆盖 Chromium 常见 WebM/Opus 以及 WebKit 可用的 MP4/AAC，不只改后缀冒充另一种编码。

服务端校验容器与内容，使用受限解码流程按 provider 需要转为受支持格式。现有 Wyoming 的 ffmpeg/afconvert 路径可提取可复用部分；部署需提供所选运行环境的解码工具并做启动能力检查。

网页麦克风需要安全上下文和用户授权。本机 loopback 开发地址可用于调试，手机通过局域网 IP 访问 HTTP 开发站不能被当作录音验收入口；手机真机使用 HTTPS。

不以浏览器 `SpeechRecognition` 作为唯一识别实现，其浏览器可用性仍有限。转写由后端统一选择现有工作区服务。

### 5.2 建议的数据结构

新增以下概念，具体列与迁移在实施阶段固定：

| 结构 | 主要字段与约束 |
| --- | --- |
| `plan_drafts` | workspace、owner、source_type、音频私有引用、audio_revision/digest、转写原文、用户修订文本、input_revision、draft_revision、基准时间/时区、结构化提案、状态、timestamps |
| `plan_jobs` | workspace、draft、stage=transcribe/generate、音频/输入版本、草稿基线版本、上下文 hash、provider profile version、状态、租约/心跳、attempt、retry_at、错误码 |
| `plan_commits` | workspace、draft、确认版本/hash、幂等键、生成实体映射与成功回执；成功提交对 `(workspace_id, draft_id)` 唯一 |

音频通过现有工作区对象存储写入私有对象，浏览器不接触服务端凭据。上传字节在数据库事务外完成；大小、摘要和对象持久化成功后，用短事务确认音频关联。中断产生的孤立对象由可靠清理作业处理。

建议音频用于校对期间保留，提交成功或删除草稿后进入清理；未完成草稿音频默认保留 7 天，界面显示到期时间。已过期音频不影响保存的文字和计划继续编辑。此为拟定保留策略，可配置；不改变既有语音笔记的删除策略。

`plan_drafts` 是该功能自己的输入记录，可在通用 Capture 模块完成后通过引用整合，不双写出第二份相同笔记/捕获实体。第一版草稿只由创建者访问，其他成员和移动端不自动收到原始录音。

### 5.3 作业与版本控制

- ASR/LLM 外部调用放在 SQL 事务外；作业可持久恢复、重试或取消，短事务提交结果。
- 每次执行解析工作区当前租户运行时；最终写入用 epoch 保护，不用旧转写 worker 启动时持有的固定 Store 代替解析。
- 重录或替换音频推进 audio_revision 并记录 digest；修改文字、时区、基准时间、目标项目或其他生成上下文推进 input_revision；用户改提案推进 draft_revision。转写 job 绑定音频版本、摘要与文字基线版本；生成 job 绑定输入版本、草稿基线版本和上下文 hash。作业仅在相关版本仍匹配、租约有效时应用结果。
- 迟到的旧转写不能覆盖用户已修改的文字；旧生成结果不能覆盖新草稿。重新生成也不能修改已经成功提交的草稿。
- 作业持久化错误码，避免把带密钥的 provider 原始错误写入数据库或日志。

### 5.4 建议 Web 接口

以下为新增协议提案，不代表当前已经存在。均走网页现有认证、工作区授权和运行时解析，无须网页调用 mobile-v1 接口。

| 接口 | 用途 |
| --- | --- |
| `GET /api/planning/capabilities` | 可否录音转写/文字生成、限制、不可用原因 |
| `POST /api/plan-drafts` | 保存文字或创建音频草稿，记录基准时间、时区与目标项目上下文 |
| `GET /api/plan-drafts?status=open` | 当前用户最近未完成草稿，支持重新进入 |
| `GET /api/plan-drafts/:id` | 恢复文字、提案、版本和处理中状态 |
| `PUT /api/plan-drafts/:id/audio` | 上传音频，校验大小、摘要和 expected_revision；同音频重传幂等 |
| `POST /api/plan-drafts/:id/transcribe` | 幂等提交转写作业，202 返回 job_id |
| `PATCH /api/plan-drafts/:id` | 用 expected_revision 修改文字、项目、勾选或任务安排 |
| `POST /api/plan-drafts/:id/generate` | 对指定输入版本生成提案，202 返回 job_id |
| `POST /api/plan-drafts/:id/validate` | 返回草稿问题、预览窗口、冲突与确认 token |
| `POST /api/plan-drafts/:id/commit` | 提交指定草稿版本与选中项，返回创建批次与实体映射 |
| `DELETE /api/plan-drafts/:id` | 取消未提交草稿并触发音频清理，不删除已创建任务 |
| `GET /api/plan-jobs/:id` | 查询阶段、进度、错误与可重试状态 |
| `POST /api/plan-jobs/:id/retry`、`.../cancel` | 重试仍有效的输入版本或取消当前作业 |

第一版使用 TanStack Query 对活跃 job 做短轮询，完成或页面不可见时降低/停止轮询；刷新后用 job_id 恢复。之后有明确体验需要再上 SSE。

创建、上传确认、转写、生成和 commit 都有稳定请求身份。同键同请求重放返回原结果，同键不同请求返回 409；不同幂等键也不能让同一 draft 成功提交两次。版本冲突返回当前 revision，保留用户本地输入。

### 5.5 确认创建的事务边界

新增 `CommitPlanDraft` 应用用例，复用或提取领域规则与可共享事务端口，不能简单循环调用当前各自开启事务的 CreateTask façade。

单次租户事务内完成：

1. 校验 actor/owner/工作区权限并解析可用的租户运行时，先按幂等键和 draft 查询成功回执、比对原请求 hash；同内容重放直接返回原实体，不再要求原 draft_revision 或预览 token 仍有效。已完成草稿的不同内容请求返回冲突。
2. 仅首次提交继续校验当前 runtime epoch、可变 draft_revision、选中项与确认内容 hash；通过草稿锁定/版本检查和成功提交唯一约束处理并发确认。
3. 校验目标项目状态和 revision；仅用户明确选择时创建新项目。规划中项目提供“仅保存为任务草稿”或“启用项目并开始执行”；暂停/结束/归档项目不被静默激活。
4. 复验支持的 schedule、due_at 和预览窗口内冲突。新的阻塞问题或需确认的重叠返回 409，整批不写入。
5. 创建稳定映射的 Task、Schedule 与初始 Occurrence；按确认选项 publish。未来重复执行仍交由现有生成器按窗口生成，不一次展开无限未来。
6. 同事务保存来源映射、draft 提交状态、成功回执和 v2 变化事件。事务失败全部回滚。

确认按钮按所选动作显示“创建并开始执行”或“保存为 N 个任务草稿”。只有符合发布/项目状态规则的任务才算可执行成功。提交成功后网页刷新工作台、项目、任务、日历和计数查询；规范实体变化继续进入现有 mobile-v2 change/snapshot，不引入第二套任务表。

## 6. 实施批次与验收

| 批次 | 交付 | 验收重点 |
| --- | --- | --- |
| A：文字到计划闭环 | 草稿/版本、AI schema、预览表单、批量 commit、成功定位 | 一次描述拆成多任务；确认前无任务副作用；重试无重复；同批失败无半成品 |
| B：网页录音接入 | 权限、计时、上传、格式归一化、转写作业、失败恢复 | Chrome/Android Chrome/iPhone WebKit；真实语音能转写；文字可纠正；不会自动增加笔记 |
| C：增强计划与发布验收 | 周期约束、有限窗口冲突、澄清、草稿恢复、回归与真实环境验收 | 日期不漂移；重复执行不重复建 Task；确认过期正确报错；创建后任务/日历/同步一致 |

A、B、C 共同构成第一版，不把只有文字生成或页面 mock 当作语音功能已经交付。先实施 A 可以隔离排查计划质量、事务一致性与语音兼容问题；网页用户拿到的是完整闭环。

必测用例：

- 权限拒绝、空录音、设备异常、超时长/超体积、实际 MIME 与声明不符、WebM/MP4 解码失败。
- 上传失败重传、ASR/LLM 服务不可用、取消、作业超时/重试、进程重启、旧结果迟到。
- 编辑转写后重生成、改项目、取消选中、字段不足、unsupported recurrence、午夜重试、DST 与周末约束。
- 双击确认、不同幂等键并发确认、提交响应丢失后重试、项目并发变更、任务创建中途故障。
- 未安排/日期/时间块、计划时段与截止时间区分、草稿内部与已有日程冲突、非无限窗口保证。
- 跨工作区猜测草稿/job/对象 ID 无法读取或修改；过期租约/epoch 无法写入。
- 创建并发布后工作台、项目详情、日历一致；只有保存任务草稿时不冒充可执行安排。

实施时更新 `docs/frontend-web-regression-checklist.md`，增加对应自动化测试，并按 AGENTS.md 从 frontend 运行 `npm run test:regression`，包含 lint、全部 Vitest、生产 build、桌面 Chrome/Android Chrome/iPhone WebKit UI 套件。fixture 通过之外，还需在规范 v2 测试环境完成真实录音 → 对象存储 → ASR → LLM → commit 验证，确认认证工作区和 MinIO binding 正确。手机录音增加 HTTPS 真机检查。
